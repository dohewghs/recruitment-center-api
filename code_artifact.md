# 🛠 Серверна частина (Backend) — Проєкт «Рекрутинговий центр»

Цей документ поєднує опис технічної архітектури серверної частини (REST API) та актуальну документацію для взаємодії з клієнтським вебзастосунком (Frontend) і базою даних PostgreSQL.

---

## 1. Обрані технології (Стек)

Серверна частина реалізована в межах **PERN-стеку** (PostgreSQL, Express, React, Node.js):

* **Середовище виконання:** Node.js
* **Фреймворк:** Express.js (маршрутизація та створення REST API)
* **База даних:** PostgreSQL (хмарний хостинг **Neon.tech**)
* **Хостинг API:** **Render** (налаштовано автоматичний деплой із GitHub)
* **Основні бібліотеки:**
  * `pg` — драйвер для підключення та виконання SQL-запитів до PostgreSQL.
  * `cors` — налаштування крос-доменних запитів для взаємодії з Frontend.
  * `dotenv` — безпечне зчитування змінних середовища (паролів і конфігурацій).

---

## 2. Реалізована архітектура проєкту

Для зручності підтримки та масштабування код розділено на логічні шари (Layered Architecture). Усі 16 SQL-запитів винесено в окремі файли та згруповано за бізнес-сутностями:

```text
recruitment-center-api/
├── db.js                  # Налаштування підключення до БД Neon
├── index.js               # Точка входу: middleware (cors, json) та підключення роутів
├── queriesSQL/            # 16 чистих SQL-файлів (1.sql – 16.sql)
├── queriesJS/             # Модулі завантаження SQL, згруповані за сутностями
│   ├── index.js           # Хелпер loadSql() для зчитування .sql файлів
│   ├── centers.sql.js
│   ├── instructors.sql.js
│   ├── inventory.sql.js
│   ├── marks.sql.js
│   ├── recruits.sql.js
│   ├── sessions.sql.js
│   └── subdivisions.sql.js
├── controllers/           # Обробка вхідних параметрів, виклик БД, формування JSON
└── routes/                # Мапінг URL-адрес на відповідні контролери
```

---

## 3. Підключення до Бази Даних

Підключення до хмарної бази даних PostgreSQL на **Neon.tech** реалізовано через бібліотеку `pg` із використанням захищеного рядка підключення (`DATABASE_URL`):

1. Конфіденційні дані (логін, пароль, хост) зберігаються локально у файлі `.env` (додано в `.gitignore`), а на продакшені — в **Environment Variables** на Render.
2. Сервер зчитує `DATABASE_URL` на старті за допомогою `dotenv`.
3. Налаштовано обов'язкове SSL-шифрування (вимога Neon).

## 4. Взаємодія з Frontend (Параметри та Відповіді)

### Отримання параметрів від клієнта
Сервер підтримує три стандартні способи передачі даних від Frontend:
1. **Параметри запиту (Query Strings)** — для фільтрації та пошуку:
   * *Приклад:* `/api/recruits/missed-sessions?title=Тактична підготовка&n=2`
   * *Обробка:* `const { title, n } = req.query;`
2. **Параметри шляху (URL Params)** — для ідентифікації конкретного запису:
   * *Приклад:* `/api/recruits/10`
   * *Обробка:* `const id = req.params.id;`
3. **Тіло запиту (Request Body)** — для передачі JSON-об'єктів (POST/PUT):
   * *Обробка:* `const data = req.body;`

Усі вхідні змінні передаються в PostgreSQL виключно через параметризовані запити (плейсхолдери `$1`, `$2`, ...), що гарантує захист від SQL-ін'єкцій.

### Формат відповідей
* API повертає результати виключно у форматі **JSON** (`res.json(result.rows)`).
* Використовуються стандартні HTTP статус-коди:
  * `200 OK` — запит успішно виконано;
  * `400 Bad Request` — не передано або некоректно передано обов'язкові параметри;
  * `404 Not Found` — запис не знайдено;
  * `500 Internal Server Error` — внутрішня помилка сервера або БД.

## 5. Документація API (Контракт для Frontend)

**Базова адреса (Base URL):**
* **Production (Хмара):** `https://recruitment-center-api.onrender.com`
* **Локально:** `http://localhost:3000`

> **Примітка:** Сервер працює на безкоштовному тарифі Render. Якщо до API не було звернень понад 15 хвилин, перший запит може виконуватися до 30–50 секунд (поки сервер «прокидається»), усі наступні запити працюють миттєво.

### Реалізовані маршрути (Endpoints)

#### 1. Отримати список усіх рекрутингових центрів (тестовий маршрут)
* **Метод:** `GET`
* **URL:** `/api/recruitment_centers`
* **Параметри:** Немає
* **Приклад відповіді (`200 OK`):**
  ```json
  [
    {
      "center_id": 1,
      "name": "Центр Львів-1",
      "city": "Львів",
      "address": "вул. Городоцька, 10"
    }
  ]
  ```

#### 2. Рекрути за датою призначення (`1.sql`)
* **Метод:** `GET`
* **Базовий префікс:** `/api/recruits/appoinment-date`
* **Параметри:** Query-параметри відповідно до контролера `getByAppointmentDate`.

#### 3. Рекрути, які пропустили більше ніж N сесій на курсі (`16.sql`)
* **Метод:** `GET`
* **URL:** `/api/recruits/missed-sessions`
* **Обов'язкові Query-параметри:**
  * `title` — назва навчального курсу (рядок)
  * `n` — мінімальна кількість пропусків (ціле число)
* **Приклад запиту:**
  `/api/recruits/missed-sessions?title=Базова військова підготовка&n=2`
* **Приклад відповіді (`200 OK`):** Масив об'єктів із полями `recruit_id`, `full_name`, `title`, `missed_sessions`.
