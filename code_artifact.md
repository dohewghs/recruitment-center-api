# Архітектура серверної частини (Backend)
**Проєкт:** «Рекрутинговий центр»

Цей документ описує технічні рішення, обрані для реалізації серверної частини застосунку, механізми взаємодії з базою даних та клієнтською частиною (Frontend).

## 1. Обрані технології
Для реалізації проєкту було обрано класичний **PERN-стек** (без React на стороні сервера). Серверна частина побудована на таких технологіях:
* **Середовище виконання:** Node.js.
* **Фреймворк:** Express.js (забезпечує швидке створення REST API та маршрутизацію).
* **База даних:** PostgreSQL (хмарний хостинг на Neon.tech).
* **Основні бібліотеки:** 
  * `pg` — для виконання SQL-запитів до бази даних.
  * `cors` — для забезпечення безпечного крос-доменного доступу з боку Frontend.
  * `dotenv` — для безпечного керування секретними ключами та конфігураціями.

## 2. Підключення до Бази Даних
Підключення до хмарної бази даних PostgreSQL (Neon) реалізовано за допомогою драйвера `pg` через механізм безпечних рядків підключення (Connection Strings).

**Процес підключення:**
1. Рядок підключення (з логіном, паролем та хостом) зберігається у захищеному файлі `.env` (або в Environment Variables на хмарному хостингу Render). Це гарантує, що паролі не потраплять у публічний репозиторій.
2. Сервер зчитує змінну `DATABASE_URL` за допомогою бібліотеки `dotenv`.
3. Створюється екземпляр `Client` з бібліотеки `pg`, де налаштовується обов'язкове використання SSL (вимога сервісу Neon).
4. Під час старту сервера відбувається виклик `client.connect()`, після чого бекенд готовий маршрутизувати SQL-запити.

## 3. Отримання параметрів від клієнта (Frontend)
Сервер приймає вхідні дані та фільтри від клієнтського вебзастосунку трьома способами, залежно від типу запиту:

1. **Параметри шляху (URL Params):** Використовуються для ідентифікації конкретного ресурсу. 
   * *Приклад URL:* `/api/recruits/10`
   * *Обробка на сервері:* `const id = req.params.id;`
2. **Параметри запиту (Query Strings):** Використовуються для фільтрації, пошуку та сортування результатів.
   * *Приклад URL:* `/api/recruits?specialty=sniper&status=active`
   * *Обробка на сервері:* `const { specialty, status } = req.query;`
3. **Тіло запиту (Request Body):** Використовується для створення нових записів (POST) або оновлення наявних (PUT), де дані передаються у форматі JSON.
   * *Обробка на сервері:* `const data = req.body;`

Усі параметри перед передачею в SQL-запит проходять параметризацію (використання плейсхолдерів `$1, $2...`), що повністю захищає базу даних від SQL-ін'єкцій.

## 4. Повернення результатів
Сервер функціонує як RESTful API. Взаємодія з Frontend відбувається виключно у форматі **JSON**.
* Після виконання SQL-запиту через `client.query()`, сервер отримує масив рядків (`result.rows`).
* Цей масив конвертується у JSON та відправляється клієнту за допомогою методу `res.json()`.
* Залежно від результату операції сервер повертає відповідні HTTP статус-коди (наприклад, `200 OK` при успіху, `404 Not Found`, якщо дані не знайдено, `500 Internal Server Error` при помилках БД).
